1. THE VISION

Transform NeverSoft CMD into the most capable, polished, and extensible Android terminal and AI computing environment realistically achievable without root.

Imagine combining:

- Termux's real Linux command execution and package ecosystem.
- A modern desktop development workstation.
- Open-Mine's futuristic control-center design direction.
- VS Code's project management and development workflow.
- An integrated AI agent capable of executing natural-language instructions.
- Kali-style security research tools for authorized environments.
- A local LLM runtime and model manager.
- A Linux distribution manager.
- An automation and agent orchestration platform.

All contained within one standalone Android application.

This must not be a simulation, launcher, terminal-themed dashboard, or collection of nonfunctional UI panels.

The terminal, filesystem, package manager, development tools, and process execution must actually work.

Nonnegotiable principles

1. Functionality before appearance, but deliver both.
2. Offline-first architecture.
3. Native ARM64 performance whenever possible.
4. No dependence on an installed Termux application.
5. Every button performs a real action.
6. Modular architecture with independently replaceable components.
7. Persistent state, sessions, and workspaces.
8. Accurate reporting of what the device can and cannot execute.
9. No placeholder implementations in production.
10. Do not declare completion until a real Android device passes acceptance testing.

5. BUILT-IN NATURAL-LANGUAGE COMMAND ENGINE

Create an optional conversational terminal mode named VIBE.

The user should be able to type ordinary instructions instead of shell commands.

Examples:

"Find all my Python environments and tell me which ones are broken."

"Update Artemis and check whether its dependencies still work."

"Start my local GGUF model server."

"Clone this repository, install its dependencies, and build the APK."

"Find the process using port 8080 and tell me what it is."

"Check why my agent stopped responding."

Inference architecture

Use a hybrid system:

Layer 1 — Deterministic intent router

Recognize common commands without requiring a model.

Layer 2 — Small local LLM

Support Qwen3-1.7B or another benchmarked lightweight instruction model.

The model must be optional and downloadable rather than forcing a large APK installation.

Layer 3 — Advanced reasoning provider

Allow switching to larger local models or cloud APIs for complex work.

Layer 4 — Authorized execution engine

Convert validated instructions into real operations.

Execution pipeline

Interpret → Plan → Validate → Authorize → Execute → Observe → Verify → Report.

Never assume a generated command succeeded merely because it ran.

Require approval for destructive actions, privilege changes, external data transmission, and sensitive filesystem operations.

Provide an emergency stop button.
